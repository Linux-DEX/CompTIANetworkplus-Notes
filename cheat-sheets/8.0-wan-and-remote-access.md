# 8.0 WAN and Remote Access — cheat sheet

## WAN

- Leased line = reserved bandwidth. T1 = 1.544 Mbps, 24×64 kbps. CSU/DSU at the demarc.
- Circuit switching = ISDN. BRI = 2B+D. Packet switching = Frame Relay, ATM, MPLS. CIR is what you are promised, not the port speed.
- Metro Ethernet = an Ethernet handoff you do not control the middle of.
- CWDM = few wavelengths. DWDM = many, long haul.
- MPLS forwards on a label. A carrier MPLS VPN is a private VRF. It is separation, not encryption.
- Know the circuit ID. Monitor the handoff, not only the LAN.

## Voice and last mile

- LTE/5G is the backup WAN. WiMAX is the name to recognize. GSM had SIMs. CDMA mostly did not.
- SIP = signaling, 5060/5061. RTP = the audio, UDP. G.711 ≈ 64 kbps. G.729 ≈ 8 kbps.
- About 150 ms one way before conversation breaks. Jitter is the variation. QoS without a queue does nothing.
- A SIP trunk replaces a PRI. No audio after setup is usually NAT rewriting the signaling and not the media address.
- PPP authenticates with PAP (clear) or CHAP (challenge). PPPoE is PPP on Ethernet. MTU 1492. Small sites load, big transfers hang, if ICMP is filtered.
- DMVPN = spokes build direct tunnels. The hub is not in the data path afterward.

## VPN

- Remote-access = a person. Site-to-site = two gateways. Split tunnel = only office traffic. Full tunnel = everything.
- IPSec ESP encrypts. AH does not. Tunnel mode wraps the whole packet (site-to-site). Transport mode does not.
- IKE is UDP 500. NAT-T is UDP 4500. GRE does not encrypt. PPTP is retired.
- SSL VPN rides 443 and gets through networks that only allow the web.
- Peer addresses must be reachable without the tunnel. Do not NAT the traffic that should be tunneled.
- Overlapping `192.168.1.0/24` on the home LAN and the office makes a tunnel that comes up and reaches nothing.
- Keep an out-of-band path. The VPN you just broke cannot fix itself.
