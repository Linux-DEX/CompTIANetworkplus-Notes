# 13.2 EVPN, BFD, and Microsegmentation

Section **13.0 Current practice**. VXLAN and spine-and-leaf are in 12.1 and 12.2. Routing timers are in 7.3. VLAN segmentation is in 4.5. This note is how a current data center learns addresses, notices a dead link, and limits east-west traffic.

## EVPN

**EVPN** (Ethernet VPN) is a **BGP** control plane for layer-2 and layer-3 segments. In a data center the data plane is usually **VXLAN** (12.2): the frame still rides inside UDP 4789. EVPN is how the VTEPs learn where a MAC and an IP live, instead of flooding that question across the fabric.

Each VTEP speaks BGP and advertises what it has learned.

| Route | What it advertises |
|---|---|
| Type 2 | A MAC address, and often the IP that sits on it |
| Type 3 | Which VTEPs are members of a VNI, so broadcast and multicast have a distribution list |
| Type 5 | An IP prefix, for routing between subnets across the fabric |
| Type 1 | An Ethernet segment, used when one server is dual-homed to two leaves |

**ARP suppression** follows from the type-2 routes. A leaf that already learned the IP-to-MAC mapping from BGP can answer the local ARP. The request does not have to be flooded to every other leaf.

**Distributed anycast gateway** puts the same gateway IP and the same gateway MAC on every leaf that serves that subnet. A server's first hop is the leaf it is plugged into. Traffic to another subnet is routed there, instead of crossing the fabric to one central gateway and back.

Multihoming is the other reason EVPN shows up. Two leaves can both be active toward one server (an Ethernet segment). BGP tells the rest of the fabric that either leaf is a valid way to that MAC. A design that still blocks one of those links with spanning tree has spent the EVPN work and then thrown away the second path.

EVPN uses route distinguishers and route targets the way an MPLS L3VPN does (8.1). The underlay only has to route between VTEP addresses. It does not learn the servers' MAC addresses.

## BFD

**BFD** (Bidirectional Forwarding Detection) is a small hello that runs between two neighbors, separate from the routing protocol. OSPF, BGP, EIGRP, and static routes can all subscribe to the same BFD session.

Routing protocols have their own timers, often measured in seconds. BFD is often set to a few tens or hundreds of milliseconds, and it declares the neighbor dead after about three missed hellos. The routing protocol then withdraws the paths that used that neighbor.

| Point | Why it matters |
|---|---|
| It detects forwarding failure | A link can stay "up" at layer 1 while the path is black-holing. BFD notices the missing hellos |
| It is aggressive | On a congested or lossy link, hellos get dropped and BFD flaps a healthy neighbor. Protect the hellos with QoS, and do not pick a 50 ms timer on a path that cannot carry it |
| It is per neighbor | A routing adjacency that is not tied to BFD still waits for its own timer |
| Micro-BFD | On a link bundle, a session per member link finds the one bad member instead of waiting for the whole bundle to look dead |

Use it where failover time is the requirement: a data-center fabric, a WAN edge with two carriers, a pair of routers running FHRP. A desktop VLAN does not need it.

## Microsegmentation

A VLAN cuts a broadcast domain (4.5). Two servers in the same VLAN can still talk on every port. **Microsegmentation** puts a policy on that conversation: this web tier may open TCP 443 to that app tier, and nothing else, even though both sit in `10.1.20.0/24`.

| Where the rule lives | What enforces it |
|---|---|
| The host or the hypervisor | A distributed firewall on the virtual switch. Traffic between two guests on one host is still inspected |
| The cloud | A security group on each instance (12.3) |
| The switch | ACLs, or a tag such as a security group tag that follows the user or the workload |
| Identity | The rule names the application and the account, which is the zero-trust version of the same idea (12.2) |

East-west traffic (12.1) is the traffic this is for. A perimeter firewall never sees it.

The hard part is the allow list. Enforce a default deny before you know the real flows, and you will break the application that calls a port you did not document. Collect flows first (NetFlow, a capture, the application's own map), write the narrow allows, then deny the rest. A rule of "any to any inside the VLAN" is the old network with a new product name.
