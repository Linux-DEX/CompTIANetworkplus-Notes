# 10.4 Mitigation, Policy, and Wireless Security

Section **10.0 Security**.

## Controls, matched to the failure

| Failure | Mitigation |
|---|---|
| Open unused ports | Shut them. An open port with a default VLAN is a free drop |
| Any device may join | 802.1X, or at least MAC allow-lists where 802.1X will not run. MAC filters are weak. They are better than nothing on a printer VLAN |
| Users reach servers they should not | VLAN plus an ACL or a firewall. The VLAN alone is not the rule |
| Management reachable from users | A management VLAN, and SSH only from a jump host |
| No record of what happened | Syslog or a SIEM, with clocks synced, retained longer than the incident-discovery delay |
| One account can do everything | Separate admin accounts, not a daily login that is also a domain admin. Privilege that is standing is privilege that will be phished |
| Firmware and OS are old | A patch cycle with a window and a backout (9.5). "We will get to it" is how known bugs stay |
| Remote admin over Telnet or HTTP | SSH and HTTPS only. Disable the others on the device, not only on the firewall |
| Backups exist and have never been restored | A restore test. An untested backup is a hope |

**User education** is a control for the failures technology does not see: a phone call that asks for a password, a USB stick in the parking lot, a door held open. It works when it is specific ("this is what our IT will never ask") and when reporting is easy. A yearly video that nobody can connect to last week's incident does very little.

**Acceptable-use policy** is the written rule: what the network may be used for, what monitoring exists, and what happens when the rule is broken. A policy nobody was shown is not a policy. It is a document.

## Hardening a network device

- Change default passwords. Remove default SNMP communities.
- Disable unused services (Telnet, HTTP, unused routing protocols, CDP or LLDP on the edge if you do not want to advertise the platform).
- Timeouts on management sessions. Logging of commands.
- NTP, so the logs have times.
- A current firmware that is not also brand new this morning, unless this morning's version is the fix for the incident you are having.
- The management plane reachable only from where administrators sit.

## Wireless security

| Scheme | Standing |
|---|---|
| Open | No encryption. A captive portal is not encryption. Anyone in radio range sees the traffic |
| WEP | Broken. Do not use it. Recognizing it on a scan is a finding |
| WPA | Interim. The TKIP cipher is retired |
| WPA2-Personal | AES (CCMP) and a shared passphrase. Fine for a home. Weak for a company, because the passphrase is the same for everyone and an evil twin can use it too |
| WPA2-Enterprise | 802.1X against RADIUS. Per-user credentials. The AP proves itself with a certificate. This is the office network |
| WPA3-Personal | A better handshake (SAE) so a weak passphrase is harder to attack offline |
| WPA3-Enterprise | The current enterprise target, with stronger encryption options |

Guest wireless is a separate SSID, a separate VLAN, and a firewall rule that lets it reach the Internet and not the office. A guest passphrase on a slip at the reception desk is acceptable exactly because that VLAN cannot reach payroll.

**Client isolation** stops wireless clients from talking to each other. Turn it on for guests. Leave it off for a staff SSID only if staff devices actually need to see each other.

**Hide the SSID** does not secure anything (1.7). **MAC filtering** is bypassed by anyone who can hear a permitted MAC. Neither replaces WPA2 or WPA3.

A wireless IDS watches for rogue APs (an AP whose SSID is yours and whose BSSID you did not install) and for deauthentication floods that kick clients off so they will join something else. The response is to find the radio, not only to block the MAC, because the radio can change its MAC.

## Policies worth having on one page

- Who may approve a firewall change.
- How long logs are kept.
- How a lost laptop is reported, and how fast its access is revoked.
- Which data may leave the building, and by what channel.
- A change window, and what counts as an emergency (9.5).

Write them down, name an owner, and review them when the network changes. A policy that describes the office you had five years ago will be ignored, correctly.
