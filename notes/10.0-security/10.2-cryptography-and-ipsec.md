# 10.2 Cryptography and IPSec

Section **10.0 Security**.

Cryptography does three jobs: hide the content, show whether it was changed, and prove who sent it. A protocol that only does one of those is not "encrypted" in the sense people mean.

## The building blocks

| Idea | What it is |
|---|---|
| Symmetric | One shared key encrypts and decrypts. Fast. AES is the one you want. The problem is getting the same key to both sides without someone else seeing it |
| Asymmetric | A public key and a private key. You encrypt to the public key, or you sign with the private key. RSA and elliptic curve. Slower. Used to exchange a symmetric key and to sign |
| Hash | One way. SHA-256 is current. MD5 and SHA-1 are broken for security decisions. A hash is not encryption. Anyone can recompute it |
| HMAC | A hash that also uses a key, so an attacker who can modify the message cannot recompute a valid tag |
| Digital signature | A hash of the message, encrypted with the sender's private key. Anyone with the public key can verify. Provides integrity and origin |
| Certificate | A public key signed by a certificate authority, plus a name and a validity period. Binds "this key" to "this name" |
| PKI | The system of CAs, certificates, and revocation (CRL or OCSP) that makes signatures mean something outside one room |

**In transit** is TLS, IPSec, SSH. **At rest** is disk and file encryption. You usually need both. TLS does not help a stolen backup tape.

**Perfect forward secrecy** means today's session keys cannot be recovered later if the long-term key is stolen. Modern TLS does this with ephemeral Diffie-Hellman. A certificate still authenticates the server. The certificate is not the session key.

## TLS, the practical version

HTTPS is HTTP inside TLS. The server presents a certificate. The client checks that a trusted CA signed it, that the name matches the site, and that it is not expired or revoked. Then the two sides agree on a symmetric key and the HTTP is encrypted.

A private CA for internal sites is normal. Every client has to trust that CA. A user who clicks through a warning has turned the check off. That is the failure mode, not a workflow.

## IPSec

IPSec protects IP packets. It is the usual site-to-site VPN and one of the remote-access VPNs (8.3).

| Piece | Role |
|---|---|
| IKE / IKEv2 | Negotiates the algorithms and the keys. UDP 500. IKEv2 is the one to use |
| ISAKMP | The framework IKE uses to exchange the proposals. People say ISAKMP when they mean IKE |
| SA | A security association: one negotiated set of keys and algorithms, in one direction. Traffic needs a pair |
| AH | Authentication Header. Integrity and origin. No encryption. Rare on its own, and NAT breaks it |
| ESP | Encapsulating Security Payload. Encryption plus integrity. This is the one you want |
| Transport mode | Protects the payload. The original IP header stays. Host to host |
| Tunnel mode | Wraps the entire original packet in a new IP header. Gateway to gateway. This is the site-to-site VPN |
| NAT-T | UDP 4500. ESP does not survive NAT, because NAT changes fields the integrity check covers. NAT-T wraps it in UDP |

Both ends must agree on the proposal (encryption, hash, Diffie-Hellman group) and on how they authenticate (a pre-shared key or certificates). Certificates scale. A pre-shared key that is in every router's config and in three people's mail is not a secret.

A policy says which traffic enters the tunnel (the proxy identities, the subnets). Traffic that should be tunneled must not be NAT'd first (8.3). Traffic that should go to the Internet in the clear must not match the policy, or you will try to encrypt a packet toward a peer that is not the Internet.

## Key handling

- Do not invent a cipher. AES, SHA-256, TLS 1.2 or 1.3, IKEv2.
- Rotate anything that has been exposed. Rotation you have never practiced will fail on the day you need it.
- A key stored next to the data it protects does not protect the data.
- Longer is not a substitute for "known broken". A long MD5 password hash is still MD5.
