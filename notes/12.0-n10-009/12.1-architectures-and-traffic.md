# 12.1 Architectures and Traffic Flows

Section **12.0 Network+ N10-009**. Cable shapes (bus, star, ring, mesh) are in 1.3. This note is how a campus and a data center are built, which is what the current exam asks.

## Three-tier hierarchical model

A campus that has grown past one closet is drawn as three layers. Each layer has one job. Mixing the jobs is how a "core" switch ends up doing access-port security and melting under it.

| Layer | Connects | Job | What you do not put here |
|---|---|---|---|
| Access | PCs, phones, APs, printers | VLANs, PoE, port security, the edge | The default route for the whole company |
| Distribution | The access switches | Inter-VLAN routing, ACLs, redundancy (FHRP), aggregation | End-user ports |
| Core | The distribution blocks, and the way out | Fast transport between blocks. Redundant, routed | Per-user policy, if you can keep it off |

Traffic from a PC to a server in another building goes access, distribution, core, distribution, access. The core's only question is "which distribution block?"

A **hub-and-spoke** WAN is the same shape with different words: sites (spokes) connect to a central site (hub). Spoke-to-spoke traffic crosses the hub unless you add a shortcut (DMVPN, 8.2). A **star** is the LAN name for one central device and many leaves. A **point-to-point** link has two ends and nobody else.

## Collapsed core

A small or mid-size site merges **core and distribution** into one pair of switches. Access stays its own layer. You have fewer boxes and the collapsed layer does both transport and policy. That is the right design until the policy load, or the number of access closets, justifies a separate core. Calling a two-switch network "three-tier" on a diagram does not make it one.

## Spine and leaf

A data center that is mostly servers talking to servers does not want a deep tree. **Spine-and-leaf** is a two-layer fabric:

- **Leaf** switches connect to servers (and to the way in and out of the room).
- **Spine** switches connect only to leaves. Every leaf connects to every spine.
- Spines are not cabled to each other. Leaves are not cabled to each other.

Any server reaches any other server in the same number of hops: leaf, spine, leaf. Add capacity by adding a spine (every leaf grows a link) or a leaf (servers land there, and it uplinks to every spine). The links are routed, and **ECMP** spreads flows across the equal paths. A blocked spanning-tree link in this design is wasted money; the fabric is built so STP is not the redundancy plan.

```text
        spine     spine     spine
          |  \   / | \     / |
          |   \ /  |  \   /  |
        leaf  leaf  leaf  leaf
         | |   | |   | |   | |
       servers ...
```

## North-south and east-west

| Flow | Direction | Example |
|---|---|---|
| North-south | In and out of the data center | A user on the Internet or in the office hitting a web server. Firewall and load balancer sit on this path |
| East-west | Between systems inside the data center | An app server calling a database, a backup, a storage array. Often most of the bits |

A design that inspects only the front door misses east-west. A compromised web server reaches the database on a path that never saw the perimeter firewall. Segmentation and ACLs between those tiers are the control (4.5). Spine-and-leaf exists because east-west traffic punishes a tree that was built for users-to-Internet.

## What the diagram is hiding

- A three-tier drawing with one link between layers is a drawing of an outage. Each layer pair wants two links and two devices.
- A spine-leaf with a leaf missing one spine uplink still works and is no longer equal-cost. Fix the missing link before you call the fabric done.
- Hub-and-spoke fails at the hub. Two hubs, or a second path, is the availability plan (9.3).
