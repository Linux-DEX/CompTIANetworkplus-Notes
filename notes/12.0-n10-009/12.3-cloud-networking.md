# 12.3 Cloud Networking

Section **12.0 Network+ N10-009**. Service models (IaaS, PaaS, SaaS) are in 1.8. The storage network and the basic VPC are in 11.2. This note is the connectivity and the firewall objects the current exam names.

## What you are renting

| Model | Who owns the hardware | Who else is on it |
|---|---|---|
| Public | The provider | Other customers. Isolation is configuration plus the provider's hypervisor |
| Private | You, or a provider running a cloud that only you use | Your organization |
| Hybrid | Both | The office and the public cloud, connected on purpose |

**Multitenancy** means the public cloud runs many customers on shared hosts and shared networks. Your security group is the wall between you and the neighbor. Their outage can still be your outage when the shared control plane fails. That is the trade for not owning the building.

| Word | Meaning |
|---|---|
| Scalability | The design can grow: a bigger instance, another node, another region. You planned the growth |
| Elasticity | Capacity is added and removed as load moves, without a change ticket for each step. Addresses behind a service will change (11.2) |

A system can scale (you can add servers) and still fail to be elastic (nobody added them until the users had already left).

## Network functions virtualization

**NFV** runs a function that used to be an appliance — router, firewall, load balancer, WAN edge — as software on ordinary servers. The function is a virtual machine or a container. You add capacity by adding instances, and you place the function where the traffic is. The failure mode moves from "the appliance died" to "the host, the orchestrator, or the license count died." SDN (11.1) decides the path. NFV is the path's appliances, virtualized. They are often deployed together and they are not the same layer.

## The VPC, and the two firewalls

A **virtual private cloud** is your IP space inside the provider: subnets, route tables, and a way out (11.2). Two different objects filter packets. People open the wrong one and then wonder why the instance is still dark.

| Object | Attached to | State | What you write |
|---|---|---|---|
| Security group | An instance or its interface | Stateful. Return traffic for an allowed flow is allowed | Mostly allow rules. A web server allows 443 in. You do not also write the reply |
| Network security list (NACL) | A subnet | Stateless. Each direction is its own rule | Numbered rules, first match. Allow the request and allow the reply, including the ephemeral ports |

A security group that allows `0.0.0.0/0` on every port is a host on the Internet. A NACL that allows the request and forgets the return looks like a black hole: the SYN arrives, the SYN-ACK dies. Check both before you rebuild the instance.

Do not overlap the VPC's ranges with the office. A VPN between two networks that both use `10.0.0.0/16` does not have a route. It has a conflict.

## Gateways

| Gateway | What it is for |
|---|---|
| Internet gateway | Attached to the VPC. A subnet with a route to it, and instances with public addresses, talk to the Internet directly. This is the front door |
| NAT gateway | Sits in a public subnet. Instances in a private subnet use it as their outbound path. They reach the Internet. The Internet does not open connections to them. You still need a route and you still pay for the bytes |

A private subnet with no route to a NAT gateway and no public address has no Internet. That is correct for a database. It is a ticket when the database subnet was supposed to pull patches.

## How the office reaches the region

| Path | Character |
|---|---|
| VPN over the Internet | Fast to start. Throughput and latency are whatever the Internet is that hour. Encrypts. Good default for a branch |
| Direct connect (private circuit into the region) | A dedicated path. Predictable, another circuit ID to monitor, and it does not encrypt by itself unless you add that |

**Shared responsibility** does not move because the circuit is private. The provider secures the building and the hypervisor. You secure the guest, the security group, the routes, the data, and the accounts.

## Content delivery network

A **CDN** stores copies of content at edges near users. DNS or anycast sends the client to a nearby cache. A hit never crosses your WAN. A miss is fetched from the **origin** and then cached.

Use it for objects that many people fetch and that can be slightly stale: images, software downloads, video. Do not point it at a page that is different for every user unless you understand what is cached. The origin still needs a firewall. A CDN in front of an open bucket hides the latency and does not hide the data.
