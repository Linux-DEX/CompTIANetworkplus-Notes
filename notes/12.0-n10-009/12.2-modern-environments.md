# 12.2 Modern Network Environments

Section **12.0 Network+ N10-009**. SDN and the basic SD-WAN idea are in 11.1. IPv6 dual stack and tunnels are in 6.3. This note is the rest of objective 1.8: the words the current exam uses for overlay, trust, and automation.

## SD-WAN, the four properties

An SD-WAN edge sits at each site. A controller holds the policy. The **underlay** is whatever IP you bought (MPLS, broadband, LTE). The **overlay** is the tunnels.

| Property | What it means on a Tuesday |
|---|---|
| Application aware | Voice can prefer the low-loss circuit while a backup takes the cheap one. The choice is per application, not one default route for the site |
| Transport agnostic | The overlay does not care which underlay carried the packet. Add LTE without redesigning the routing protocol |
| Central policy management | You change the rule once on the controller. You do not paste it onto forty routers |
| Zero-touch provisioning | A new edge is shipped to a site, plugged in, and pulls its config. Nobody consoles it in a closet with a laptop, if the design is honest |

The underlay can still be down. SD-WAN picks among paths that exist. It does not invent a circuit.

## VXLAN

A VLAN ID is 12 bits: **4094** usable networks. A data center that hosts many customers runs out. Stretching those VLANs across a routed fabric with trunks also stretches broadcasts and spanning tree.

**VXLAN** (Virtual Extensible LAN) carries an Ethernet frame inside a UDP packet. The underlay is ordinary IP routing (often spine-and-leaf, 12.1). The overlay looks like a LAN to the servers.

| Piece | Role |
|---|---|
| VTEP | Virtual tunnel endpoint. The switch or the hypervisor that encapsulates and decapsulates |
| VNI | The overlay ID, 24 bits, on the order of 16 million segments |
| UDP 4789 | The port the encapsulated frames use |
| Underlay | Routed IP. The VTEPs must be able to reach each other |

**Data center interconnect (DCI)** is the same idea between buildings or regions: a layer-2 segment that rides a layer-3 path, so a live migration (11.1) can land in the other room. The cost is the failure domain. A broadcast storm in a stretched segment is a storm in both data centers. Stretch a VLAN only when the workload truly needs one subnet in two places.

## Zero trust

**Zero trust architecture (ZTA)** treats the network location as untrusted. A laptop on the office VLAN still authenticates, and it still receives only the access that identity is allowed. The perimeter firewall remains useful. It is no longer the only decision.

| Piece | Meaning |
|---|---|
| Policy-based authentication | Every request is checked against a policy: who, what device, what they are asking for |
| Authorization | A successful login is not a blank check. The policy names the applications |
| Least privilege | The account, the VLAN, and the rule allow the minimum the job needs (10.1) |

A VPN that drops a user onto the whole internal network is the old model with a tunnel. Zero trust replaces that landing zone with access to specific applications.

## SASE and SSE

**SASE** (Secure Access Service Edge) delivers the WAN path and the security stack from a cloud edge close to the user: SD-WAN, firewall, secure web gateway, and access control, as one service. The user connects to a nearby point of presence. Traffic is inspected there. It does not all hairpin through the office.

**SSE** (Security Service Edge) is the security half of that, without the SD-WAN: web gateway, cloud access broker, and zero-trust access to applications. You still buy connectivity separately.

The objectives PDF once prints SASE as "Secure Access Secure Edge." The acronym list and the product name are **Service** Edge. Remember Service.

## Infrastructure as code

**Infrastructure as code (IaC)** stores the network's intended state as files: templates, playbooks, reusable tasks. A tool applies the file to the devices. The alternative is a human pasting a config at 02:00 and forgetting what they pasted.

| Idea | What you are buying |
|---|---|
| Playbooks and templates | The same VLAN, ACL, or BGP neighbor built the same way on every box |
| Source control | A central repository, history, and a branch for a change that is not ready. A conflict is two people editing the same intent |
| Dynamic inventory | The list of devices is generated (from IPAM, from the controller), so a new switch is not missing because a text file is stale |
| Upgrades | The firmware version is declared, and the tool can tell you who is behind |
| Configuration drift | The running config no longer matches the file. Drift is how an emergency change becomes the undocumented permanent one |
| Compliance | A scheduled comparison of live devices against the golden file (12.4). A difference is a ticket, not a surprise during an outage |

The tool does not know your intent. A bad template applied cleanly is an outage you can reproduce. Review the diff the way you review a firewall change (9.5).

## IPv6 compatibility, the three options

Address exhaustion is why IPv6 exists (6.3). Getting there has three patterns the exam names:

| Pattern | What runs |
|---|---|
| Dual stack | IPv4 and IPv6 on the same interfaces. DNS has A and AAAA. This is the usual enterprise path |
| Tunneling | IPv6 carried inside IPv4 where the path is still v4-only (6in4 and its relatives) |
| NAT64 | IPv6-only clients reach IPv4 servers. A DNS64 resolver invents an AAAA for a name that has only an A record, and a NAT64 router rewrites the packet. The server sees IPv4 |

NAT64 is the one you pick when the clients will not have an IPv4 address. Dual stack is the one you pick when both stacks are still in production.
