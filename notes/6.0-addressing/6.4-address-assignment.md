# 6.4 Address Assignment

Section **6.0 Addressing**. IPv6 assignment is in 6.3. This note is how an interface gets an IPv4 address, and the IPv6 methods side by side.

## Static

An administrator sets address, mask, gateway, and DNS on the host. Use it for anything that other systems look up by address: routers, switches, firewalls, servers, printers that people print to by IP. Record it, and keep it **out of the DHCP pool**.

## DHCP

Dynamic Host Configuration Protocol leases an address from a pool. The client does not have an address yet, so the first messages are broadcasts. Ports are UDP 67 (server) and UDP 68 (client).

**DORA:**

| Step | Message | What happens |
|---|---|---|
| Discover | Client broadcast | "Is there a DHCP server?" |
| Offer | Server | "You can have this address, for this long." |
| Request | Client broadcast | "I accept that offer." Broadcast so any other server withdraws |
| Ack | Server | The lease is confirmed, with mask, gateway, DNS, domain name, and other options |

A **lease** has a time. At 50% (T1) the client asks the same server to renew, unicast. At 87.5% (T2) it asks any server. If the lease expires with no answer, the client drops the address and starts over. A short lease suits a guest Wi-Fi. A long lease suits desktops.

A **reservation** (DHCP reservation) pins one MAC to one address, served by DHCP so the settings stay central. It is not the same as a static address configured on the host. The host still speaks DHCP. The server just always hands back the same number.

A **relay** (ip helper) is required when the server is not on the LAN. Routers do not forward the client's broadcast. The router turns it into a unicast aimed at the configured helper address and stamps the LAN's gateway address on it, so the server knows which pool to use.

## APIPA and link-local

If no DHCP server answers, Windows (and others) self-assign `169.254.0.0/16` and check for a duplicate with ARP. There is **no default gateway** and no DNS. The host can talk to other APIPA hosts on the same link and nowhere else. Seeing 169.254 on a PC means DHCP failed: the server is down, the VLAN has no helper, or the client is on the wrong VLAN.

IPv6 always has `fe80::/10` as well, whether or not SLAAC or DHCPv6 worked. A v6 link-local address does not mean autoconfiguration failed.

## IPv6, short

| Method | Who picks the address |
|---|---|
| Static | Administrator |
| SLAAC | The host, from the prefix in a Router Advertisement |
| DHCPv6 | A server, stateful |
| SLAAC + stateless DHCPv6 | Host picks the address, server supplies DNS and other options |

## BOOTP

BOOTP is DHCP's predecessor and uses the same ports. DHCP added leases, more options, and the relay behavior above. You will see the name. You will deploy DHCP.

## What to check when a client has the wrong address

- 169.254: no DHCP reached the client.
- An address from the wrong subnet: the client is on the wrong VLAN, or a rogue DHCP server answered first.
- A duplicate-address warning: a static host sits inside the pool, or two reservations share an address.
- Correct address, no name resolution: DHCP options are missing the DNS server, or the DNS server is wrong (6.5).
- Works on the LAN, no Internet: the gateway option is missing or points at a dead router.

## DORA with addresses on it

A laptop with MAC `00:11:22:33:44:55` joins VLAN 10. It has no address yet. The server `10.1.1.5` lives on another subnet. The router `10.10.10.1` is the relay.

| Step | From | To | What is in it |
|---|---|---|---|
| Discover | `0.0.0.0:68` | `255.255.255.255:67` | The MAC, and a request for an address. A broadcast. The router is the only reason this reaches `10.1.1.5` |
| Offer | The server, via the router | The client, still at broadcast or its MAC | "You may use `10.10.10.50/24` for 8 hours. Gateway `10.10.10.1`. DNS `10.1.1.5`." |
| Request | The client, broadcast again | The servers | "I want the offer from that server." Any other server that offered something else withdraws |
| Ack | The chosen server | The client | The lease is real. The client may use the address |

The relay writes the LAN's gateway address into the packet (the **giaddr**). That is how the server knows this client belongs in the `10.10.10.0/24` pool and not the server room's pool. A helper pointed at the wrong server, or a server with no scope for that giaddr, produces silence, then a `169.254` address.

The words the exam uses for the configuration, separate from the four messages:

| Word | What you configure |
|---|---|
| Scope | One subnet's pool: the network, the mask, and the range that may be leased |
| Exclusion | Addresses inside the scope that must not be leased, because a router or a printer already uses them statically |
| Reservation | One MAC always receives one address. The client still uses DHCP |
| Lease time | How long the address is valid. Guest Wi-Fi: hours. A desktop floor: days |
| Options | The extras in the Ack. The ones that matter are the mask (option 1), the router (3), the DNS servers (6), and the domain name (15) |
| Relay / IP helper | The router command that turns the client's broadcast into a unicast toward the server |

At half the lease (T1, 4 hours on an 8-hour lease) the client unicasts a renew to the same server. At about 87.5% (T2) it will accept a renew from any server. If the clock runs out with no answer, it drops `10.10.10.50` and starts Discover again. Users notice that moment as "the network blipped," because every existing connection was using an address the host no longer owns.
