# 6.6 Proxy Servers and NAT

Section **6.0 Addressing**.

## Proxy

A proxy makes a request **on behalf of** a client. The server sees the proxy, not the laptop.

| Kind | Behavior |
|---|---|
| Forward proxy | Clients are configured (or forced) to send web traffic to it. Used for caching, filtering, and logging |
| Reverse proxy | Sits in front of servers. The Internet talks to it, and it talks to the real web servers. Load balancing, TLS offload, and hiding the origin |
| Transparent proxy | Intercepts traffic without the client being configured. A firewall redirects port 80 or 443 at it |
| Caching proxy | Stores answers. The second request for the same object does not cross the WAN |

A **PAC file** or **WPAD** tells the browser which proxy to use, and which destinations to skip. Getting WPAD wrong sends internal traffic out through a proxy that cannot reach it, or sends everything direct and bypasses the filter.

Proxies are application-aware. A web proxy understands HTTP. It does not, by itself, carry a VPN or a random UDP flow. That is a difference from NAT, which rewrites IP headers and does not care what the payload is.

## NAT

Network Address Translation lets many private hosts share a smaller set of public addresses. The NAT device rewrites the source (or destination) address as the packet crosses it, and keeps a table so the reply can be translated back.

Four addresses show up in the vocabulary. "Inside" is your network. "Local" is the address as seen on your network. "Global" is the address as seen on the outside.

| Term | Example |
|---|---|
| Inside local | `10.0.0.5`, the PC |
| Inside global | `203.0.113.10`, what the Internet sees as that PC |
| Outside global | `198.51.100.20`, the real web server |
| Outside local | How that server is addressed from inside, if you also translate it. Often the same as outside global |

### Forms

| Form | What it maps |
|---|---|
| Static NAT | One private address always becomes the same public address. Used for a server that must be reachable from outside |
| Dynamic NAT | A pool of public addresses, handed out one per internal host, first come first served. When the pool is empty, the next host waits |
| PAT, overload, NAT overload | Many private hosts share **one** public address. The device also rewrites the source **port**, and the table is keyed by that port. This is what a home router does |

PAT is the one you will actually deploy for users. Static NAT is the one you add for a published server. Dynamic NAT without ports is uncommon now because public addresses are scarce.

### What NAT breaks

- End-to-end addressing. A host outside cannot open a connection to `10.0.0.5` unless you added a static mapping or a port forward.
- Protocols that embed an IP address inside the payload (old FTP active mode, SIP). The header is translated and the payload still says the private address, so the far side tries to reply to an address it cannot route. An application-layer gateway, or a protocol that is NAT-aware, fixes that specific case.
- IPSec in tunnel mode, unless you use NAT-T (UDP 4500), because NAT changes the address that the integrity check covered.
- Logging. After PAT, the identity of a user is "public IP plus source port plus time", and only the NAT table or the proxy log can turn that back into a person.

### Port forwarding

A static entry that says "public address, TCP 443, goes to `10.0.0.20:443`". That is how a private web server is published. Every forward is a hole. Publish the port the application needs, and nothing else.

Double NAT (your router, then the ISP's carrier-grade NAT on `100.64.0.0/10`) means you do not have a public address of your own. Inbound forwards on your router never see the Internet. A tunnel that originates outbound is the usual way through.
