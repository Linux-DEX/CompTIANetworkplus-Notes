# 6.5 DNS

Section **6.0 Addressing**.

DNS turns a name into an address, and a few other record types besides. Without it, every client would need the IP of every server, and those IPs would never be allowed to change. Port **53**. Queries are UDP. Zone transfers and answers that do not fit in a UDP message use TCP.

## The hierarchy

The tree is read from the right.

```text
www.example.com.
```

The trailing dot is the root. From the right: root, top-level domain (`com`), second-level domain (`example`), then the host label (`www`).

| Piece | Role |
|---|---|
| Root servers | Know which servers hold each TLD. Named like `a.root-servers.net` |
| TLD servers | `.com`, `.org`, a country code. Know which servers hold each domain |
| Authoritative server | Holds the real records for `example.com` |
| Recursive resolver | The server your PC actually asks (often the ISP, or 8.8.8.8, or the domain controller). It walks the tree for you and caches the answer |

**Recursive** query: the client says "go find the whole answer." That is what a PC sends its resolver.

**Iterative** query: "tell me the next step, I will ask them." That is how the resolver talks to root, TLD, and authoritative servers.

A **forwarder** is a resolver you have told to hand questions it cannot answer to another resolver, instead of walking from the root itself. Internal DNS servers commonly forward public names outward and answer internal names themselves.

## Records

| Type | Holds |
|---|---|
| A | Name to IPv4 |
| AAAA | Name to IPv6 |
| CNAME | An alias. `www` is a CNAME to `server1`. A CNAME should not sit at the zone apex next to other records, and mail is not sent to a CNAME |
| MX | Mail exchanger, with a preference number. Lower number is tried first |
| NS | Which servers are authoritative for the zone |
| PTR | Address to name. Lives in the reverse zone (`1.168.192.in-addr.arpa`), not in the forward zone |
| TXT | Free text. SPF, DKIM, and site verification live here |
| SRV | Host and port for a service. Active Directory and SIP use these |
| SOA | Start of authority: primary server, contact, serial, refresh, retry, expire, minimum TTL |

**TTL** is how long a resolver may cache the answer. Lower it before a migration, wait out the old TTL, then change the record. Changing an A record with a one-day TTL does not move the world today.

## Zones

A **zone** is the part of the tree one set of servers is authoritative for. A **forward zone** is name to address. A **reverse zone** is address to name.

The **primary** holds the writable copy. **Secondaries** transfer it (AXFR for the whole zone, IXFR for the changes) over TCP/53. The SOA serial number must increase or the secondary will not bother. Lock transfers to the secondary's address. An open AXFR hands a stranger the map of your network.

**Internal DNS** answers names that exist only inside (`files.corp.example`). **External DNS** answers the names the Internet should see (`www.example.com`). They are often different servers on purpose. Splitting them is **split horizon**: the same name can resolve to a private address inside and a public address outside.

## Dynamic DNS

DHCP can update DNS when it hands out a lease, so `laptop42.corp.example` follows the client. Active Directory depends on this. If the update is refused, clients have addresses and no names, and directory logins fail.

## Integrity and privacy of the lookup

**DNSSEC** signs the records so a validating resolver can reject a forged answer. It does not encrypt the query. **DoT** encrypts the lookup on TCP 853. **DoH** encrypts it inside HTTPS on 443, which hides it among web traffic. Detail and the authoritative-versus-cache distinction are in 12.4.

## Failure patterns

- `ping 1.1.1.1` works and `ping example.com` does not: the path is fine, DNS is not. Check the configured resolver, then whether UDP/53 and TCP/53 leave the network.
- Some names work and the internal ones do not: the PC is using a public resolver that has no view of the internal zone. DHCP should hand out the internal resolver.
- One site resolves, another does not, and the TTL is long: a stale cache. The serial on the secondary may also be stuck because the transfer failed.
- Mail vanishes: the MX is missing, points at a CNAME, or the preference order sends everything at a dead host first.
