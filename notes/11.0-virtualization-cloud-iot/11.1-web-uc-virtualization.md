# 11.1 Web Services, Unified Communications, Virtualization, and SDN

Section **11.0 Virtualization, Cloud, and IoT**.

## Web services

A **web service** is an application talking to another application over HTTP, not a person with a browser. The page you load is often ten of these calls.

| Style | What it looks like |
|---|---|
| REST | Resources and HTTP methods. `GET /users/12`. Usually JSON. Stateless, so any server in the pool can answer |
| SOAP | XML, a formal contract, heavier. Still around in enterprises |
| Webhook | The server calls you when something happens, instead of you polling |

They ride the same ports as the web (80, 443) and the same load balancers. A firewall that "allows HTTPS" has allowed every API that speaks HTTPS. Filtering them is an application decision (identity, a specific path), which is why an NGFW or an API gateway exists. TLS is not optional on these. The payload is often a credential or a customer record.

## Unified communications

**UC** is voice, video, presence, and messaging as one system rather than a phone system plus a separate chat. The network sees SIP for signaling, RTP or SRTP for media, and a bunch of HTTPS for the client. Requirements are the voice requirements from 8.2, plus enough bandwidth for video, which dwarfs a phone call. A 720p call is on the order of 1–2 Mbps. Ten of them are a WAN circuit.

QoS still matters on a congested link. On a lightly loaded gigabit LAN you will not see it. The WAN and the Wi-Fi cell are where UC falls apart. Wi-Fi has to prioritize the voice SSID or the voice frames (WMM), or a large download on the same AP will step on the call.

## Virtualization

A **hypervisor** schedules guest machines onto one physical host. Each guest has virtual CPU, RAM, disk, and NICs.

| Type | Where it sits |
|---|---|
| Type 1, bare metal | On the hardware. ESXi, Hyper-V in its server role, KVM. This is the data center |
| Type 2, hosted | On top of a normal OS. The laptop lab |

A **virtual switch** on the host connects the guests to each other and, through an uplink, to the physical network. Two guests on the same vSwitch never hit the physical wire. A capture on the physical switch will not see that traffic. If you need to inspect it, you span it on the virtual switch or you route it through something you can see.

**vMotion / live migration** moves a running guest to another host. The guest keeps its MAC and its IP. The physical switches must learn the MAC on the new port immediately, and the VLAN must exist on the destination. A guest that moves to a host where the VLAN was not trunked disappears.

Snapshots and oversubscription are the operational traps. A snapshot that was "just for the upgrade" and is still there a year later fills the disk and freezes the guest. A host that has promised more RAM than it has will run until every guest needs it at once.

## SDN

**Software-defined networking** separates the decision from the forwarding.

| Plane | Job |
|---|---|
| Data (forwarding) | Moves the packets. The switch ASIC |
| Control | Decides where they should go. In SDN this is a controller, not a config file on each box |
| Management | How you talk to the system. The API and the GUI |

The controller tells the switches what to do, often with **OpenFlow** or with the vendor's API. You change a policy once. The controller pushes it. The failure mode is the controller: if the switches cannot stand alone when the controller is unreachable, the controller is now as important as a core router, and it needs the same care (redundancy, a backup, a change window).

**SD-WAN** is the WAN version. Each site has an edge device. A controller picks the path (MPLS, broadband, LTE) per application, based on loss and latency, instead of one static default route. The underlay is whatever IP connectivity you bought. The overlay is the encrypted tunnels. You are not freed from the underlay being down. You are freed from configuring every tunnel by hand and from sending voice across a link that is currently losing packets.

VXLAN, zero trust, SASE, and infrastructure as code are in 12.2. The four SD-WAN properties the current exam names are there too.
