# 11.2 SAN, Cloud, and IoT

Section **11.0 Virtualization, Cloud, and IoT**. Cloud service models (IaaS, PaaS, SaaS, NaaS) are in 1.8. This note is the storage network, how you connect to a cloud, and the devices that are not computers.

## Storage area networks

A **SAN** presents blocks, like a disk. A **NAS** presents files, like a share (SMB or NFS). The exam's storage network is the SAN.

| Fabric | How the servers reach the disks |
|---|---|
| Fibre Channel | Its own network, its own switches (a fabric), HBAs instead of NICs. Not IP. Addresses are World Wide Names. Designed not to drop frames |
| FCoE | Fibre Channel frames inside Ethernet. Not routable. Needs a lossless Ethernet (priority flow control). Stays inside the data center |
| iSCSI | SCSI commands over TCP. Ordinary NICs, ordinary IP, ports 860 and 3260. Routable, and therefore easy to point at the wrong network if you are careless |

Separate the storage traffic from the user traffic. A backup that shares a path with the guests' LAN will lose to them, or they will lose to it. Jumbo frames, if you enable them, must match on the server, the switch, and the array (4.2). One device left at 1500 black-holes the large frames.

**Zoning** (Fibre Channel) and **LUN masking** limit which server can see which disk. A server that can see another server's disk will write to it. Multipathing gives the server two fabrics so one switch failure is not an outage. Both paths in the same cable tray are not two fabrics.

## Cloud, the network parts

The service models are in 1.8. The network questions are about how traffic gets there and who controls it.

| Connection | Trade |
|---|---|
| Internet and a VPN | Fast to start. Quality and the public address are whatever your ISP is today |
| Private circuit into the provider (Direct Connect, ExpressRoute, and the equivalents) | A dedicated path into the cloud region. Predictable, and another circuit to monitor |
| Public endpoint | The service has a public name and TLS. Simple, and the identity check is the entire access control |

A **virtual private cloud** is a routed IP space you define in the provider's network, with subnets, route tables, and a security-group firewall. It is your design, on their underlay. The same mistakes are available: a security group that allows `0.0.0.0/0`, a subnet that overlaps the office, a default route that points somewhere you did not mean.

**Elasticity** means the provider adds or removes capacity as load moves. Your monitoring has to expect the IP addresses behind a service to change. Pin the dependency to a name or a load-balancer address, not to a single virtual machine's address.

**Shared responsibility:** they secure the building and the hypervisor. You secure the guest OS, the security group, the data, and the accounts. "It is in the cloud" is not a control. An open storage bucket is your configuration.

## IoT

**Internet of Things** is the label for sensors, cameras, badges, bulbs, and controllers that speak IP and were not designed as computers. They are numerous, rarely patched, often default-passworded, and they sit next to the things they sense.

| Practice | Why |
|---|---|
| Their own VLAN and SSID | A camera does not need to reach the file server. When it is compromised, the blast radius is the camera VLAN |
| No default passwords | These devices ship with published credentials. Changing them is the whole control on many of them |
| They do not need the Internet by default | A sensor that only talks to a local controller should not have a default route. Egress that is denied unless required is visible when something starts calling home |
| Know which ones you have | An inventory. An unknown device on the network is either a mistake or someone else's |
| Industrial IoT and SCADA | Segmented harder, not softer (4.5). Availability and physical safety outrank convenience |
| Patch where the vendor still ships patches | Many of these devices will never see another firmware. Isolation is the compensation |

A smart-home protocol on an office SSID is shadow IT with a radio. The guest or IoT VLAN is where it goes, if it is allowed at all.
