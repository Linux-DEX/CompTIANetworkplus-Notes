# 8.2 Voice, Cellular, and Last-Mile Links

Section **8.0 WAN and Remote Access**.

## Cellular

These are the wide-area radios a failover modem or a phone uses. Generations matter more than the brand name.

| Name | What it is |
|---|---|
| GSM | The original digital cellular family. SIM cards. The base of what became 3G UMTS and then LTE |
| CDMA | The competing North American family. Historically no SIM. Largely retired as a data path |
| LTE (4G) | The data network that replaced both for Internet access. A USB or Ethernet modem in a closet is usually LTE or 5G |
| 5G | Higher rates and, in some bands, coverage that is worse indoors. Not a LAN technology |
| WiMAX | An attempt at metropolitan wireless broadband (IEEE 802.16). You should recognize the name. You are unlikely to deploy it |

A cellular backup is a second default route with a worse administrative distance (7.2), so it is used only when the primary WAN drops. It is a shared, metered, higher-latency path. It is not where you replicate a SAN.

## Voice over data

Once voice is packets, it is ordinary traffic with an unusually low tolerance for delay and jitter. Packet loss that a file transfer will retransmit becomes a hole in a syllable.

| Piece | Role |
|---|---|
| IP phone or softphone | The endpoint. It needs power (PoE) and a voice VLAN |
| IP PBX or a cloud PBX | Extensions, voicemail, dial plan |
| SIP | The signaling. Sets up and tears down the call. Ports 5060 and 5061. The audio is a separate RTP stream, not on 5060 |
| RTP | The audio packets. UDP, even port numbers, negotiated per call |
| Codec | How the audio is compressed. G.711 is about 64 kbps and sounds like the phone network. G.729 is about 8 kbps and sounds worse. The two ends must share a codec |
| Voice gateway | Converts between IP and the PSTN when the other party is on a normal number |
| QoS | Queues voice ahead of backups. Mark it (DSCP, often EF) and configure the queue. Marking without a queue does nothing |

**Latency** budget for a call is on the order of 150 ms one way before people start talking over each other. **Jitter** is variation in that delay. A jitter buffer hides a little of it by holding packets briefly, and adds delay of its own. **Loss** above a couple of percent is audible.

A **SIP trunk** is the carrier product that replaces a PRI: the phone company speaks SIP to your PBX over the Internet or over a private link, instead of handing you a T1. The addressing inside SIP is a classic NAT problem (6.6). The provider's SBC (session border controller) or an ALG has to rewrite it, or calls set up and then have no audio.

## PPP, PPPoE, DMVPN

**PPP** is the point-to-point layer-2 protocol used on serial links and on dial-up. It does framing, authentication (PAP or CHAP), and multilink (bonding two circuits). PAP sends the password in the clear. CHAP uses a challenge so the password is not sent. Use CHAP if you are still using PPP authentication.

**PPPoE** carries PPP over Ethernet. DSL providers used it so the same username and password model worked on an Ethernet handoff. The router, not the PC, should be the PPPoE client. The MTU drops by 8 bytes. Leaving the LAN at 1500 and the PPPoE link at 1492 is a classic "small sites load, large downloads hang" fault, because path MTU discovery is being filtered.

**DMVPN** is a hub-and-spoke VPN in which spokes also build tunnels directly to each other when they need to, using multipoint GRE and NHRP to learn each other's public addresses. The hub is not in the data path for spoke-to-spoke traffic after the shortcut forms. It is a specific Cisco-style design. The exam point is: spokes can talk without a permanent mesh of tunnels you configured by hand.

A **SIP trunk**, **PPP**, and a **VPN** solve different problems. PPP is a link protocol. A SIP trunk is a phone-company signaling session. A VPN is an encrypted overlay. A diagram that draws all three as "the WAN" is three technologies stacked, not one.
