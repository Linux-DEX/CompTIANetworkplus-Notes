# 7.3 Dynamic Routing, IGP, EGP, and Loops

Section **7.0 Switching and Routing**.

Dynamic routing means routers tell each other what they can reach, and withdraw the advertisement when the link dies. You still design it. You do not turn on every protocol and hope.

## IGP and EGP

An **interior gateway protocol** runs inside one autonomous system, one organization's routing domain. An **exterior gateway protocol** runs between autonomous systems. On the Internet, that protocol is BGP.

| | IGP | EGP |
|---|---|---|
| Scope | Inside your network | Between networks, between you and an ISP, between ISPs |
| Examples | RIP, OSPF, EIGRP, IS-IS | BGP |
| What it optimizes | A metric: hops, cost, delay | Policy: which paths you are willing to use and to advertise |
| Typical size | Campus, company, a data center | The global table, or a handful of ISP uplinks |

You can run OSPF inside and BGP only on the edge. Redistribution is how routes leak from one protocol into another. Redistribute in one direction, with a filter, or you will feed a route back to the protocol that taught it to you and build a loop.

## The IGPs you have to tell apart

| Protocol | Type | Metric | Notes |
|---|---|---|---|
| RIPv2 | Distance vector | Hop count, max 15 | Sends the whole table on a timer. Fine for a lab. Slow and blind to bandwidth. v2 is classless and uses multicast 224.0.0.9. v1 is classful and broadcasts |
| OSPF | Link state | Cost from bandwidth | Every router in an area builds the same map and runs SPF (Dijkstra). Fast, scales by splitting into areas. Area 0 is the backbone. All other areas must touch it |
| EIGRP | Advanced distance vector | Bandwidth and delay | Cisco. Backs up a feasible successor so failover can be immediate. Uses a topology table, not only the best route |
| IS-IS | Link state | Cost | Same family of idea as OSPF. More common in large service-provider cores than in a small enterprise |

**Distance vector:** "I know these prefixes, this many hops away." The router does not know the map, only the rumors from neighbors. **Link state:** "Here is every link I touch." Every router computes the map itself.

RIP's **split horizon** does not advertise a route back out the interface it was learned on. **Poison reverse** advertises it back with an infinite metric instead, so the neighbor drops it immediately. Both exist to stop the simplest loop.

## BGP, only as far as the exam goes

BGP speaks prefixes between autonomous systems and attaches attributes (weight, local preference, AS-path length, and others). The AS path is the list of systems a route crossed. A router that sees its own AS in the path rejects the route. That is BGP's loop prevention.

You do not need a full BGP design here. You need: eBGP is between different AS numbers, iBGP is inside one AS, and BGP will happily do what you tell it, including advertising a route you cannot actually reach. Filters are part of the configuration, not an extra.

## Routing loops

A loop is a packet that returns to a router it already visited. TTL (hop limit) is the backstop: at zero the packet is dropped and ICMP time exceeded is sent. Traceroute showing the same two addresses forever is the symptom. The cure is in the protocol, not in raising the TTL.

| How loops happen | What stops them |
|---|---|
| Distance-vector rumor during a failure (counting to infinity) | Split horizon, poison reverse, hold-down timers, a low maximum hop count (RIP's 15) |
| Redistributing a route back into the protocol that owns it | Route tags, and distribute-lists so a protocol does not learn its own prefixes from outside |
| Two default routes pointed at each other | One default, toward the real exit. A floating static only if its distance is worse than the learned route |
| A static route via a next hop whose return path is this router | Fix the return route. Asymmetric is fine. Circular is not |
| Summarizing a range you do not fully own, so someone else's traffic arrives and you send it back | Summarize only blocks you are authoritative for, or black-hole the summary's unknowns with a route to null |

**Hold-down** means "I just heard this route died. Ignore a new claim that it is alive, for a while." It trades speed for stability. Link-state protocols mostly do not need it, because every router saw the same failure.

OSPF and IS-IS prevent loops by construction: each router computes a shortest-path tree with itself as root, and a tree has no cycles. They can still loop during the few seconds while neighbors have not all processed a new LSA. That is temporary. A redistribution loop is permanent until you fix the filter.

## What the routers actually say

Three routers in a line: A connected to B, B connected to C. The LAN `10.1.1.0/24` sits on A.

**RIP.** A tells B "I can reach `10.1.1.0`, one hop away." B tells C "two hops." Nobody drew a map. C only knows a rumor from B. If A's link to that LAN dies, B may still be repeating "two hops" to C while C repeats "three hops" back to B. Each round adds a hop. That is **counting to infinity**. RIP stops at 16, which it treats as unreachable, so the lie dies, slowly. Split horizon is why B should not have told A a route that B learned from A in the first place.

**OSPF.** A does not send a rumor. It floods a description of its own links, a **link-state advertisement**, to every router in the area. B and C each run SPF and build the same map. When the link dies, a new advertisement says so, and each router recomputes. The metric is **cost**, from bandwidth. With the usual reference of 100 Mbps, a 100 Mbps link costs 1, and a 1 Gbps link also costs 1, because the integer math floors it. Faster links look equal until you raise the reference bandwidth. Equal-cost paths can both be used.

**Areas.** Area 0 is the backbone. A router with one interface in area 0 and one in area 1 is an **area border router**. Area 1 learns the rest of the network through area 0. Two areas that only touch each other, with no area 0 between them, do not exchange routes the way you hoped. A small network is allowed to be a single area 0. Splitting areas is how you stop every router from holding every link.

**EIGRP** keeps a backup, the **feasible successor**, already checked, so a dead best path can be replaced without asking the neighbors again. The backup is allowed only when the neighbor's advertised distance is better than this router's current best. That rule is what keeps the backup from being a path that runs back through you.

**BGP, on one edge.** Your router and the ISP's router are **eBGP** neighbors because the AS numbers differ. Two of your own routers exchanging BGP are **iBGP**, same AS. You advertise your prefixes and you accept a default, or the ISP's routes, through a filter. Advertising `0.0.0.0/0` by mistake, or advertising a prefix you do not own, is how someone else's traffic arrives at your office and dies. RPKI (13.3) is the Internet's check on that advertisement. The filter is still yours to write.
