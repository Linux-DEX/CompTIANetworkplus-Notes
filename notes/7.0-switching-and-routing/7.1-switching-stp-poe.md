# 7.1 Switching, Spanning Tree, and PoE

Section **7.0 Switching and Routing**. What a switch is, versus a router, is in 1.8.

## What a switch does with a frame

The switch learns **source** MAC addresses and the port they arrived on, and stores them in the MAC table (CAM table). Entries age out, often in five minutes, so a moved PC is relearned.

| Frame | Action |
|---|---|
| Unicast, destination is in the table | Forward out that one port |
| Unicast, destination is unknown | Flood out every port in the VLAN except the one it arrived on |
| Broadcast or unknown multicast | Flood the VLAN |
| Frame whose source and destination are the same port | Drop. The two hosts are already on the same segment, or the table is wrong |

**Store-and-forward** receives the whole frame, checks the FCS, then sends it. **Cut-through** starts sending as soon as the destination MAC is read. Cut-through is faster and will forward a damaged frame. Store-and-forward is what you want unless you have measured a latency problem.

**ASIC** forwarding is the point of a switch. The first frame to a new destination may be handled in software. After that, the hardware table does it at line rate.

## LAN administration, the short list

- One VLAN per broadcast domain you actually want (7.4).
- Management address on a management VLAN, not on VLAN 1 if you can help it. VLAN 1 is the default and everyone knows it.
- Disable unused ports, or put them in an unused VLAN.
- Set access ports so a user cannot negotiate a trunk (BPDU Guard and disabling DTP, in 7.4).
- Save the configuration. A switch that was right until the power failed was never saved.
- Name the port after the desk or the server, in the description field. The person who comes in at 02:00 is not you.

## Spanning Tree

If two switches are connected by two links, or three switches form a triangle, Ethernet has a loop. Broadcasts circle forever. The MAC table thrashes. The network stops.

**Spanning Tree Protocol** lets the physical loops exist (you want them for redundancy) and blocks ports so the logical path is a tree.

| Idea | Meaning |
|---|---|
| Root bridge | The switch all paths aim at. Lowest bridge ID wins. The ID is a priority plus the MAC. Set the priority on the switch you want as root. Do not leave it to chance |
| Root port | The port this switch uses to face the root. One on each switch that is not the root. The root bridge itself has none. Forwards |
| Designated port | The port that forwards traffic onto a segment, chosen on the root's side of that segment. One per segment. Forwards |
| Blocked (discarding) port | The port that would complete a loop. It still receives topology messages. It does not forward user traffic |

Default IEEE cost prefers faster links: 10 Gbps is cheaper than 1 Gbps, which is cheaper than 100 Mbps.

**Convergence** is the time after a failure before the blocked port starts forwarding. Classic 802.1D could take 30 to 50 seconds (listening and learning states). **Rapid STP (802.1w)** is the one to run. It converges in seconds and is backward compatible enough to be the default on modern switches.

| Protection | What it stops |
|---|---|
| PortFast | Skips the wait on a port that is only a PC or a phone. Do not enable it on a port that connects to another switch |
| BPDU Guard | If a PortFast port receives a BPDU, shut it. Someone plugged a switch into a desk port |
| Root Guard | Refuses to accept a switch that claims to be a better root. Stops a rogue or a misconfigured switch from moving the root |
| BPDU Filter | Stops sending and processing BPDUs. Easy to create a loop with. Prefer Guard |
| Loop Guard | If BPDUs stop arriving on a blocked port, keep it blocked instead of opening it into a loop |

## Power over Ethernet

PoE sends DC power over the spare pairs, or over the data pairs, so an access point or a phone does not need a power brick.

| Standard | Rough power at the device |
|---|---|
| 802.3af (PoE) | 15.4 W from the switch, about 12.95 W at the device |
| 802.3at (PoE+) | 30 W from the switch, about 25.5 W at the device |
| 802.3bt (PoE++, type 3 and 4) | 60 W and 100 W class. Cameras, thin clients, small switches |

The switch has a **power budget**. Ten ports rated for 30 W do not all deliver 30 W if the power supply is 150 W. When the budget is spent, the next device does not boot, or the switch drops the lowest-priority port. Set priority so the access point in the stairwell is not the one that dies.

A powered device and the switch negotiate the class. A non-PoE laptop on a PoE port is fine: no negotiation, no power applied. An **injector** adds PoE on one cable run when the switch cannot. A **splitter** takes PoE off for a device that wants a barrel plug. Mode A uses the data pairs. Mode B uses the spare pairs. Gigabit has no spare pairs, so power rides the data pairs. The standard sorts this out. A cheap passive injector that always applies 48 V does not, and it can damage a device that did not ask.
