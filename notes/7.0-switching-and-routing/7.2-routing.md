# 7.2 Routing, Metrics, and Tables

Section **7.0 Switching and Routing**.

A router forwards a **packet** to a next hop based on the destination IP and a routing table. It rewrites the layer-2 frame for the outgoing link and decrements the TTL. It does not forward broadcasts.

## Connected, static, dynamic

| Route source | How it gets there |
|---|---|
| Connected | The subnet on an interface that is up. Most trustworthy. Administrative distance is usually 0 |
| Static | You typed it. It does not adapt when a link fails, unless you tied it to an interface that goes down, or you added a floating static |
| Dynamic | A routing protocol learned it from a neighbor (7.3) |
| Default | `0.0.0.0/0` (IPv4) or `::/0` (IPv6). "If nothing more specific matches, send it here." Hosts have one. Routers at the edge have one toward the ISP |

**Longest prefix match** wins. A packet to `10.1.1.5` prefers `10.1.1.0/24` over `10.1.0.0/16` over `10.0.0.0/8` over `0.0.0.0/0`. Specificity beats the order you typed the routes.

**Administrative distance** breaks ties between sources. Lower is better. Typical Cisco values, which the exam uses even when the vendor differs: connected 0, static 1, eBGP 20, OSPF 110, RIP 120, external EIGRP and internal EIGRP have their own slots. A static route will hide a learned route to the same prefix unless you raise the static route's distance on purpose (a **floating static**, the backup).

## Metrics

The metric breaks ties **inside one protocol**. It is not comparable across protocols. OSPF cost and RIP hop count are different currencies. Administrative distance picks the protocol first. The metric only matters after that.

| Protocol idea | What it counts |
|---|---|
| RIP | Hops. 15 is the maximum. A 16th hop is unreachable. It ignores link speed |
| OSPF | Cost, based on bandwidth. A 10 Gbps link is cheaper than a 100 Mbps link |
| EIGRP | A formula of bandwidth and delay, by default. Load and reliability can be added and usually should not |

A **lower metric is preferred**. If two OSPF paths have equal cost, the router can install both and load-balance (equal-cost multipath).

## Reading a table

One line contains, at least:

- Prefix and mask
- How it was learned (connected, static, OSPF, and so on)
- Metric and administrative distance
- Next hop, or an exit interface
- How long it has been there, for learned routes

```text
O    10.2.0.0/16 [110/20] via 10.1.1.2, GigabitEthernet0/0
```

`O` is OSPF. `110` is administrative distance. `20` is the OSPF cost. `10.1.1.2` is the next hop, out that interface.

If the next hop is not on a connected subnet, the route cannot be used until that next hop is itself resolved. A static route to `10.9.0.0/16` via `10.1.1.2` is useless if `10.1.1.2` is not on a network this router touches.

## Hosts have a table too

A PC's table is usually one connected subnet and one default route (the gateway from DHCP). Traffic for the local subnet is ARPed. Everything else goes to the gateway. A PC with two NICs and two default routes will send half its traffic the wrong way. One default route, on purpose.

## When the table is wrong

- No route to the destination, and no default: the router drops the packet and should send ICMP unreachable.
- A route points at a next hop that is down: the route is withdrawn if it was tied to that interface. A static route via an address (not an interface) can stick and black-hole traffic.
- Two routers point their defaults at each other: a loop, until TTL dies. Traceroute shows the same two hops repeating.
- Asymmetric paths: the way there and the way back differ. State-aware firewalls drop the return if they did not see the forward packet. The table on **both** sides has to make sense, not just the near side.
