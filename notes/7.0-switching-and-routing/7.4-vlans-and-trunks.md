# 7.4 VLANs, Trunks, and SOHO

Section **7.0 Switching and Routing**. Why you segment at all is in 4.5. This note is how a VLAN is built.

## VLAN

A VLAN is a broadcast domain defined in switch configuration. Ports in VLAN 10 cannot send a frame to ports in VLAN 20. The cables do not move. Two VLANs on one switch share that switch's fate if the switch dies. They do not share broadcasts, and they do not share traffic unless something routes between them.

| Port mode | What is plugged in |
|---|---|
| Access | One VLAN, untagged. A PC, a printer, a phone's data VLAN if you are not also tagging voice |
| Trunk | Several VLANs, each frame tagged. Switch to switch, or switch to a router that routes on a stick |
| Voice (plus access) | An IP phone. Voice frames are tagged with the voice VLAN. The PC behind the phone is untagged on the access VLAN |

VLAN IDs are 1–4094. **1** is the default. **1002–1005** are reserved leftovers from Token Ring and FDDI. Extended range above 1005 needs the switch in transparent or the modern equivalent. Use a deliberate ID. Do not leave users on VLAN 1, because every unconfigured switch on earth is also on VLAN 1, and a trunk that accidentally allows "all" will join those users together.

A VLAN is not a security boundary by itself. Anyone who can trunk, or who can move their port's VLAN, can join it. Routing between VLANs without an ACL is still full connectivity. The firewall or the ACL is the boundary. The VLAN is the broadcast cut.

## Trunking

**802.1Q** inserts a 4-byte tag: TPID `0x8100` and a TCI that holds the VLAN ID and the priority (CoS). The frame grows from a 1518-byte maximum to 1522. Switches that do not expect a tag will count it as a giant or drop it.

One VLAN on a trunk is **native** and is sent **untagged**. The native VLAN must match on both ends. If one side thinks native is 1 and the other thinks native is 10, untagged frames from one VLAN are accepted into the other. That is a leak.

**Double-tagging** is a separate attack. The sender puts two VLAN tags on one frame. The first switch strips the outer tag because it matches the native VLAN, and the inner tag then delivers the frame into a VLAN the sender's port is not in. An unused native VLAN, with the native VLAN tagged if the switch allows it, closes both the mismatch leak and this attack.

**DTP** negotiates trunk versus access. Leave it off. An access port that is willing to become a trunk will become a trunk for anyone who asks. Configure access ports as access, trunk ports as trunk, and allow only the VLANs that trunk needs (`allowed vlan`), not "all".

**Router on a stick:** one router interface, subinterfaces, each subinterface in a VLAN, the switch port a trunk. It works. It also puts every inter-VLAN packet through one link. A layer-3 switch routes those packets in hardware and is the usual design once there is more than a little traffic between VLANs.

## SOHO

A small office or home network is the same ideas with the boxes glued together. The plastic "router" is a router, a switch, a wireless AP, a DHCP server, a DNS forwarder, a NAT device, and a firewall.

| Decision | The grown-up version of the default |
|---|---|
| LAN subnet | Change it if you will VPN to an office that also uses 192.168.1.0/24 |
| Wi-Fi | WPA2 or WPA3, a real passphrase, a guest SSID on its own VLAN that cannot see the LAN |
| Management | Change the admin password. Disable remote admin from the WAN |
| DHCP | One scope, the pool not covering the router's own address |
| Updates | The firmware is the security patch. A SOHO box that has never been updated is a known-vulnerable firewall |
| DMZ host | "Put this PC in the DMZ" on these boxes often means "forward every port to it". That is not a DMZ. Forward the one port you need |

A SOHO router doing NAT is a stateful firewall only for connections that start inside. Unsolicited inbound traffic is dropped unless you forwarded a port. That default is the whole security model. Do not turn on "allow all" to make a game work. Forward the port, or do not.

## Follow one packet

A PC at `10.10.10.50` in VLAN 10 wants a server at `10.10.20.10` in VLAN 20. The PC's mask is `/24` and its gateway is `10.10.10.1`.

1. `10.10.20.10` is not in `10.10.10.0/24`, so the PC does not ARP for the server. It ARPs for the gateway.
2. The access port receives an **untagged** frame. The switch treats it as VLAN 10 because that is the port's access VLAN. The VLAN is not written on the frame yet. The port configuration supplies it.
3. The gateway is a router subinterface, or an **SVI** on a layer-3 switch: a virtual interface with the address `10.10.10.1` in VLAN 10 and `10.10.20.1` in VLAN 20. It routes. The IP packet is unchanged apart from TTL. The frame is new, built in VLAN 20, addressed to the server's MAC.
4. If the server is on another switch, the uplink is a **trunk**. The frame leaves with an 802.1Q tag of 20. The far switch reads the tag, removes it on the server's access port, and delivers an ordinary frame.

Same VLAN, different switch: the trunk still carries the tag, and nobody routes. Different VLAN, no router: the switches can trunk all day and the PC will never reach the server. The trunk moves the frame. The router changes the VLAN.

## What the three common breaks look like

| What you see | What happened |
|---|---|
| PC and server are both "up" and cannot ping, same site | They are in different VLANs and nothing routes, or an ACL on the way is dropping them |
| Works on one switch, dies as soon as the user is moved to another closet | The trunk between them does not allow that VLAN |
| Some users land in the wrong network with no address change on their PC | Native VLAN mismatch. Untagged frames are being believed by the other side as a different VLAN |
| A desk port suddenly carries every VLAN | DTP was left on, and something negotiated a trunk. The port should have been nailed as an access port |

The **VLAN database** is the switch's list of which IDs exist. Creating VLAN 20 in the database and forgetting to assign the port, or assigning the port to a VLAN you never created, both end with the port not forwarding where you expected. `show vlan` is the check (the device commands in `tools/`).
