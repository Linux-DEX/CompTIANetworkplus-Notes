# 9.1 Monitoring, Performance, and Documentation

Section **9.0 Operations and Troubleshooting**.

## What you monitor

A link light says the port is up. It does not say the circuit is full, the DNS server is slow, or the backup ran at noon and flattened the WAN. Monitor the things users actually feel.

| Signal | Tells you |
|---|---|
| Reachability | Ping or a TCP connect to the service, not only to the gateway |
| Utilization | Bits per second against the CIR or the port speed. Sustained over about 70% on a WAN means the next burst will queue |
| Errors | CRC, runts, giants, collisions. Collisions on a full-duplex port mean a duplex mismatch |
| Discards and queues | The device is dropping traffic on purpose because a buffer filled. Different from an error |
| Latency, jitter, loss | The voice and the video path. Average latency hides jitter |
| Device health | CPU, memory, temperature, power-supply state, PoE budget |
| Logs | What the device itself thought happened |

**SNMP, syslog, and a SIEM** are the plumbing. They are written up with the tools in 9.3. The decision here is what "bad" means, before you collect a year of graphs nobody looks at. A threshold without an owner is a graph. A threshold with an on-call rotation is an alert.

**Baselines** are the measurement on a normal Tuesday. Without one, every spike looks like an incident and every incident looks like a spike. Capture baseline after the network is stable, and again after a big change.

## Performance

| Problem | The usual lever |
|---|---|
| A link is full | More capacity, or move the bulk transfer off the busy hour, or cache it (a proxy, a local update server) |
| Voice suffers while the link is not full | QoS. A priority queue for the voice class. Marking at the source, trusting or rewriting at the edge |
| One flow crowds out everyone | Shaping (smooth to the CIR) or policing (drop above the rate). Shaping delays. Policing drops |
| Wireless is slow and the AP is not busy | Channel overlap, a distant client dragging the cell down to a slow rate, or interference (9.4) |
| A server is slow and the network is idle | It is the server. Prove the network with a throughput test to a second host on the same path, then stop tuning MTU |

**QoS order of operations** that matches how the boxes work: classify (ACL, VLAN, or the application's own marking), mark (DSCP at layer 3, CoS at layer 2), queue (priority for voice, a fair share for everything else), and only then shape or police on the way out. You shape the WAN edge to the CIR so the carrier is not the one dropping your voice.

Adding bandwidth is the right fix when the average utilization is honestly high. It is the wrong fix when a single unlabeled backup is the whole average.

## Documentation

The document is what the person who is not you uses at 02:00.

| Document | Contains |
|---|---|
| Physical diagram | Racks, closets, cable IDs, patch panels |
| Logical diagram | Subnets, VLANs, routing, where NAT happens |
| IP plan | Subnet, gateway, DHCP range, static hosts |
| Circuit list | Carrier, circuit ID, CIR, demarc, support number |
| Rack elevation | What is mounted where, and the asset tag |
| Port map | Switch, port, patch, wall jack, desk |
| Baseline and config backup | The last known-good configuration, stored somewhere that is not the device |
| Change log | What was done, when, by whom, and how to undo it (9.5) |

Diagrams rot. Date them. A diagram with no date is a rumor.

**Labeling** is documentation that lives on the cable. Both ends, the same ID as the port map. A tidy bundle with no labels is harder to repair than a messy one with labels.

Configurations leave the building in a backup. A switch that dies takes its running config with it if you never copied it off. Automate the copy. Test that you can restore it onto a spare, once, before you need to.
