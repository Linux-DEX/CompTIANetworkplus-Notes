# 9.3 Tools, High Availability, SNMP, Syslog, and SIEM

Section **9.0 Operations and Troubleshooting**. The command-line tests (ping, traceroute, dig, captures) are in 6.7.

## Hardware and physical

| Tool | Use |
|---|---|
| Cable tester | Wiremap: opens, shorts, split pairs, which pin lands on which pin. A link light can be up with a split pair and still fail at gigabit |
| Certifier | The expensive tester. Measures category performance (crosstalk, return loss) against the standard, and prints a pass |
| Toner and probe | Find one cable in a bundle. Put tone on one end, listen at the other. Do not tone a cable that is plugged into a switch port if you can help it |
| TDR | Time-domain reflectometer. How far down the copper the open or the short is |
| OTDR | The fiber version. Reflects light off splices, connectors, and breaks, and tells you the distance |
| Light meter | How much light arrives, against the optic's budget. Simpler than an OTDR and enough to prove a dirty connector |
| Loopback | Plug or software that returns TX to RX, so you can test a port or a circuit without the far device |
| Crimper, punch-down, fiber stripper | Make the termination. A bad crimp is the fault the tester is about to find |
| Spectrum analyzer | Who else is transmitting on this radio channel |
| Wi-Fi analyzer | Visible networks, channels, signal, and noise at the spot where the user stands |

A multimeter belongs on a phone line or a PoE argument, not as your first Ethernet test. Ethernet is not "is there voltage".

## Software

| Tool | Use |
|---|---|
| Wireshark, tcpdump | What was actually sent. Filter first |
| Port scanner | Which ports answer. Only on systems you are responsible for |
| Throughput tester | iPerf and its relatives. Separates "the link is small" from "the application is slow" |
| Protocol analyzer | The same capture, read for the conversation: retransmits, zero windows, DNS failures |
| Log review | The device already told you. Read it before you replace the device |

## High availability

The goal is that one failure does not take the service down. Every technique has a cost and a leftover failure mode.

| Technique | What still takes you down |
|---|---|
| Redundant NICs, switches, power supplies | The thing you did not duplicate: one circuit, one upstream router, one fiber into the building |
| Link aggregation | A misconfigured bundle that only one side thinks is a bundle |
| First-hop redundancy (HSRP, VRRP, GLBP) | Two routers share a virtual gateway address. The hosts never change their gateway. Both routers dying, or a split brain if they cannot see each other |
| Clustering and load balancers | A health check that marks a dead server up, or a single balancer you did not pair |
| RAID, redundant disks | A controller, a site, or a bad write that was faithfully copied to both disks |
| UPS and generator | The runtime you did not test. A UPS that has never been load-tested is a battery-shaped rumor |
| Diverse WAN carriers | Both carriers in the same trench. Ask where the fiber is physically |

**Active/active** uses both paths. **Active/passive** keeps the second idle until failover. Passive is simpler and wastes the standby. Active/active is harder to get right when the return path and the firewall state do not follow.

Test the failover. Pull the cable on purpose, during a window, once. A design that has never failed over has not been shown to fail over.

## SNMP, syslog, SIEM

**SNMP** polls. The manager asks the agent for OIDs (interface counters, CPU) on UDP 161. The agent sends a **trap** to UDP 162 when something crosses a threshold. v1 and v2c use a community string that travels in the clear and is effectively a password. v3 has users, authentication, and encryption. Use v3. Restrict which manager addresses may poll.

**Syslog** is the device pushing a text line to a collector, UDP 514, or TCP when loss matters. Severity runs from 0 (emergency) to 7 (debug). Leave debug off on a busy router or the log becomes the outage. Point every device at the collector. A log that exists only on a switch you cannot reach is not a log.

A **SIEM** collects those logs, plus firewall and server logs, and correlates them. "This account logged in from two countries in an hour" is a SIEM question. A syslog server only stores the lines. Clocks have to agree (NTP) or the correlation is fiction.

Flow data (**NetFlow**, IPFIX, sFlow) is the summary of who talked to whom, without storing every packet. It is the right tool for "what filled the WAN". A packet capture is the right tool for "what did this one session do".
