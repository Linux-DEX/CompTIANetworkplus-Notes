# 9.4 Common Issues

Section **9.0 Operations and Troubleshooting**. The order of diagnosis is 9.2.

## Wireless

| Symptom | Likely cause |
|---|---|
| Weak signal in one room | Distance, a wall, the AP in a closet, or a client at the edge of the cell. Move the AP or add one. Do not only raise the power. A loud AP that cannot hear the client's weak radio is still a bad cell |
| Works next to the AP, fails across the floor | The far side is on a slow modulation, or it is sticking to a distant AP (sticky client) instead of roaming |
| Slow for everyone, signal looks fine | Co-channel interference. Two APs on channel 1. In 2.4 GHz use 1, 6, and 11 only |
| Fine until the microwave runs | 2.4 GHz interference. Move the AP or use 5 GHz |
| Associates, no address | DHCP. The AP's VLAN has no helper, or the client VLAN is wrong |
| Associates, no Internet, address looks right | Guest isolation, a captive portal, DNS, or the firewall |
| Drops every few minutes | Power save, a driver, or the AP rebooting because PoE is over budget |
| Open network, or WEP, or a shared WPA2 passphrase on a card everyone knows | That is a configuration failure, not a radio failure. WPA2-Enterprise or WPA3 (10.4) |

A site survey measures this. Walking around with a phone is a survey. Guessing from the floor plan is not.

## Copper

| Symptom | Likely cause |
|---|---|
| No link | Open pair, wrong port, dead NIC, or the other end unplugged. Wiremap it |
| Link at 100 Mbps on a gigabit NIC | One pair is open. 100BASE-TX only needs two pairs. 1000BASE-T needs four |
| Link, terrible performance, late collisions | Duplex mismatch. One side forced full, the other fell back to half |
| Errors that rise when the lights or the lift run | EMI. Cable run parallel to power, or an ungrounded shield |
| Works when you hold the connector | Bad crimp or a failing jack |
| Intermittent, certifier fails NEXT | Split pair. The wires are punched so a pair is split across two pairs. Pinout looks "close" and is wrong |
| Exceeds 100 m | Attenuation. Shorten it or go to fiber. A longer patch cord counts |

**Bent pins, a rolled cable where you needed a straight one, and a crossover where Auto-MDI-X is absent** all present as "no link" or "link on one side". Look at the LEDs on both ends before you replace the switch.

## Fiber

| Symptom | Likely cause |
|---|---|
| No light | TX and RX swapped. Cross the patch. This is the first check |
| Low light, errors | Dirty connector. Clean it with the proper tool. Do not blow on it |
| Worked, then failed after a pull | Bend radius violated, or a connector crushed in a tie |
| One direction works | A single strand is broken, or one optic has failed. Fiber is two paths |
| Wrong optic | Single-mode optic into multimode fiber, or the wavelengths do not match. The link can be "up" and full of errors |
| Distance over the optic's budget | The spec is a budget in dB, not a hope. A light meter settles the argument |

Never look into a live fiber. The light is infrared and it is not good for an eye (10.5).

## The network, once the cable is innocent

| Symptom | Look at |
|---|---|
| Duplicate IP | Two static hosts, or a static host inside the DHCP pool. Both will have intermittent reachability. ARP flaps |
| Wrong VLAN | The port, the trunk allow-list, or the native VLAN mismatch |
| Wrong gateway or mask | The host can ping some things and not others. Check the address against the IP plan |
| DHCP exhausted | New clients get 169.254. Old leases still work. Shorten the lease or enlarge the pool |
| DNS | Addresses work, names do not (6.5) |
| Asymmetric route or a firewall dropping the return | One direction captures, the other does not |
| Broadcast storm | A loop that spanning tree is not blocking. CPU on the switches pegs. Fix the loop before you do anything else |
| MTU | Small packets work, large transfers hang. A tunnel subtracted bytes and ICMP "fragmentation needed" is filtered |
| Certificate or time | HTTPS and logins fail, ping works. Clocks or the certificate name |

Write down which of these you have already ruled out. The next person should not start by replacing the cable you already tested.
