# 5.1 IP Addresses and Conversion

Section **5.0 IP and Core Protocols**. Subnetting design (VLSM, summarization) is the next module in the course and is not in these notes yet. This file is the address itself: what the bits mean, how to convert them, and which addresses you must not assign.

## What an IPv4 address is

An IPv4 address is a **32-bit** number. People write it as **dotted decimal**: four **octets** (bytes), each 0–255, separated by dots.

```text
192.168.1.10
```

Each octet is 8 bits. The place values inside an octet, from the left, are:

```text
128  64  32  16  8  4  2  1
```

An octet is the sum of the place values where the bit is 1. 255 is every bit set. 0 is none set.

The address has two parts:

- **Network** (or network + subnet): which LAN this host is on. Routers forward using this part.
- **Host**: which interface on that LAN.

The **subnet mask** (or a prefix length such as `/24`) says where the split is. A bit set to 1 in the mask means "this bit is network". A bit set to 0 means "this bit is host".

`/24` means the first 24 bits are network. The mask is `255.255.255.0`. The last octet is the host.

## Decimal to binary

Convert one octet at a time. Ask whether the remainder is at least each place value, left to right.

**192:**

| Place | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---|---|---|---|---|---|---|---|
| Bit | 1 | 1 | 0 | 0 | 0 | 0 | 0 | 0 |

128 + 64 = 192. Binary `11000000`.

**168:**

128 + 32 + 8 = 168. Binary `10101000`.

**1:** `00000001`.

**10:** 8 + 2 = 10. Binary `00001010`.

So:

```text
192.168.1.10  =  11000000.10101000.00000001.00001010
```

Always write all 8 bits. Dropping the leading zeros is how conversions go wrong.

## Binary to decimal

Add the place values that have a 1.

```text
11111111 = 128+64+32+16+8+4+2+1 = 255
11111100 = 128+64+32+16+8+4     = 252
00001010 = 8+2                  = 10
```

## Masks you will see constantly

| Prefix | Mask | Host bits | Usable hosts on that network |
|---|---|---|---|
| /8 | 255.0.0.0 | 24 | 2^24 − 2 |
| /16 | 255.255.0.0 | 16 | 2^16 − 2 |
| /24 | 255.255.255.0 | 8 | 254 |
| /25 | 255.255.255.128 | 7 | 126 |
| /26 | 255.255.255.192 | 6 | 62 |
| /27 | 255.255.255.224 | 5 | 30 |
| /28 | 255.255.255.240 | 4 | 14 |
| /30 | 255.255.255.252 | 2 | 2 (a point-to-point link) |
| /32 | 255.255.255.255 | 0 | One address. A host route, not a LAN |

The −2 is the network address (all host bits 0) and the broadcast address (all host bits 1). Neither may be assigned to a host. A /31 is a special case used on point-to-point links (RFC 3021) where both addresses are hosts. Ignore it until a question mentions it.

## One conversion, all the way through

Address `192.168.1.10`, mask `255.255.255.0` (`/24`).

The first three octets are network, because the mask is 255 there. The last octet is host.

| | Dotted decimal | Last octet in binary |
|---|---|---|
| Address | 192.168.1.10 | `00001010` |
| Network (host bits 0) | 192.168.1.0 | `00000000` |
| First usable host | 192.168.1.1 | `00000001` |
| Last usable host | 192.168.1.254 | `11111110` |
| Broadcast (host bits 1) | 192.168.1.255 | `11111111` |

Same address, mask `/26` (`255.255.255.192`). The interesting octet is the last one, and the mask's last octet is `11000000`. The first two bits of the last octet are now network bits.

`10` is `00001010`. The network bits in that octet are `00`, so this host is in the first block of 64:

| | Value |
|---|---|
| Block size | 256 − 192 = **64** |
| Network | 192.168.1.0 |
| First host | 192.168.1.1 |
| Last host | 192.168.1.62 |
| Broadcast | 192.168.1.63 |
| Next network | 192.168.1.64 |

The block size is the spacing between network numbers. It equals 2^(host bits). For a /26, 6 host bits, 64 addresses per network, 62 usable.

`192.168.1.70 /26` falls in the next block: network `192.168.1.64`, broadcast `192.168.1.127`. It does **not** talk to `192.168.1.10 /26` without a router, even though both addresses "look like" 192.168.1.

## Classful addresses (legacy, still in the vocabulary)

Before masks were configurable, the first bits of the address implied the mask. You still need the names, because people say "a class C" when they mean a /24, and because the multicast and experimental ranges are defined this way.

| Class | First octet | First bits | Default mask | What it became |
|---|---|---|---|---|
| A | 1–126 | 0 | /8 | Huge networks. 127 is reserved and is not class A in practice |
| B | 128–191 | 10 | /16 | |
| C | 192–223 | 110 | /24 | |
| D | 224–239 | 1110 | — | Multicast. Not assigned to interfaces as a primary address |
| E | 240–255 | 1111 | — | Reserved. 255.255.255.255 is the limited broadcast |

Classful routing is obsolete. Classless routing (CIDR) sends the mask with the route. Do the math from the mask you are given, not from the class the first octet would have implied.

## Addresses with a special meaning

| Address | Meaning |
|---|---|
| `0.0.0.0` | "This host", or the default route, depending on context. Not a destination you assign to a server |
| `127.0.0.0/8` | Loopback. `127.0.0.1` is this host. Traffic never leaves the machine |
| `169.254.0.0/16` | Link-local / APIPA. The host gave up waiting for DHCP (6.4). No default gateway |
| `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` | Documentation ranges (TEST-NET). Safe to use in notes and labs on paper |
| `224.0.0.0/4` | Multicast |
| `255.255.255.255` | Broadcast on the local LAN. Routers do not forward it |

### Private ranges (RFC 1918)

These are not routed on the public Internet. A NAT device (a later module) translates them if the host needs to go out.

| Range | Prefix | How many addresses |
|---|---|---|
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8 | About 16 million |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 | About 1 million. Note **/12**, not /16. 172.32.0.0 is public |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 | 65536 |

**Public** addresses are everything else that is not reserved above. They have to be unique worldwide. You get them from a registry, usually through your ISP.

## IPv6, only so the contrast is clear

IPv6 addresses are **128 bits**, written as eight groups of four hex digits (`2001:db8::1`). `::` collapses one run of zeros. There is no broadcast; there is multicast, plus a link-local address that starts with `fe80::` on every interface. Subnetting and the header are a later module. Do not convert an IPv6 address by pretending it is four decimal octets.

## Checks before you call an address valid

- Each octet is 0–255. `192.168.1.256` is a typo, not a network.
- The host bits are not all 0 (that is the network) and not all 1 (that is the broadcast), except for the /31 and /32 cases.
- The mask is contiguous 1s then contiguous 0s. `255.255.255.0` is a mask. `255.255.0.255` is not.
- Two hosts that should talk directly need the same network number and the same mask. Same switch, different network numbers: they will ARP for each other and fail, unless a router is their gateway.
